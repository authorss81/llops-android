## Feature 1 — Persistent Recently-Used Colors & Favorites

Today `EditorScreen.kt` computes `recentColors` with a plain `remember(...)`
(`EditorScreen.kt:3595-3605`) — it's derived from the current `palette` and is
LOST every session. Add:
- A bounded, persisted "recent colors" list in `SettingsManager` (pure-JVM
  policy class e.g. `services/ColorRecentsPolicy.kt` with a cap, dedupe, and
  unit test). It records the chosen color on pick (the palette onColorSelected
  path near `EditorScreen.kt:3612`) and seeds the recents row instead of (or
  before) the in-memory one.
- A **favorites** star on swatches/a palette picker entry that persists a small
  bounded set of curated colors in `SettingsManager` (same policy style,
  `MAX_FAVORITES` cap, dedupe, test). Recents + favorites must be loaded early
  (StateFlow, no blocking read on main).

Definition of done Feature 1: switching sessions (cold-restart VM) keeps the
last used colors + favorites; caps enforced; `.editorconfig`/formatting
consistent; `ColorRecentsPolicyTest` (and favorites test) green; `assembleDebug`
green.

## Feature 2 — Minimap quick-actions (zoom-to-fit, jump-to-home)

The minimap in `AnnotationCanvas.kt` renders a polyline overview of the current
viewport (see `services/MinimapGeometryPolicy.kt` — bit-budgeted sampling) but
has NO quick-view helpers. Add small, discoverable chips/buttons anchored to
the minimap (or the canvas toolbar) that:
- **Zoom-to-fit:** fit the whole ink content into the canvas viewport
  (compute content bounds from the stroke list, clamp to `MinimapGeometryPolicy`
  / `CanvasPageBudgetPolicy` ceilings).
- **Jump/pan-home:** return the pan/zoom transform to the top-left page start
  (same transform plumbing used by double-tap or "fit" gestures today).
Both must be pure-JVM testable (a `services/CanvasNavigationPolicy.kt` that
maps content/transform state to corrected transforms; `MotionPolicy`-aware,
respect `reduce-motion`).

Definition of done Feature 2: the two actions exist, animate through the
existing transform pipeline (spring, not jump, when motion allowed), respect
minimap cost budgets, have policy unit tests; `assembleDebug` green.

## Feature 3 — Layer opacity & blend quick presets

The layer panel already exposes an opacity slider and blend
(`EditorScreen.kt:5298-5304`, `layer.copy(opacity = it)`). Add:
- A compact set of **blend-mode presets** (normal / multiply / screen / overlay /
  soft-light, whatever AGSL chart supports today for wet brushes + plain
  layers) rendered as labelled chips in the layer row.
- Persist per-layer opacity/blend choice on the layer itself (no schema change —
  reuse existing `Layer` fields; if a field for blend already exists, wire the
  UI to it — verify first with `file:line`).
- Keep capped: no new DB columns, no new native deps.

Definition of done Feature 3: blend chips applied and restored through the
existing layer update path, unit tests for the preset definitions
(`services/LayerBlendPresetPolicy.kt`), `assembleDebug` green.
