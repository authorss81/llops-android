## Part A — Trim the lingua corpus to the 24 used languages (REAL, no new deps)

`LanguageDetectionCore` (`app/src/main/kotlin/com/authorss81/noteflow/plugins/langdetect/LanguageDetectionCore.kt`)
is a pure-JVM wrapper over `com.github.pemistahl:lingua:1.2.2`
(`app/build.gradle.kts:219`, `gradle/libs.versions.toml:26`). It compiles a
24-language `SUPPORTED` subset (`LanguageDetectionCore.kt`, `object
LanguageDetectionCore` with `SUPPORTED: Map<String,String>` + a `fromLanguages`
builder), yet the ENTIRE 75-language `language-models/` corpus ships inside the
base APK because lingua bundles all model JARs as transitive resources.

Fix approach (pick one that best matches the repo's structure — do NOT invent
one that bloats the APK more):

- **Preferred:** add AGP `packaging.resources.excludes` / `jniLibs`/resources
  exclusions in `app/build.gradle.kts` (inside the `android { packaging {
  resources { excludes += ... } } }` block) so the 51 unused language directories
  under `language-models/` are stripped from the assembled APK while the 24
  used ones remain. Verify the exact resource path layout lingua ships
  (e.g. `language-models/*/` where `*` = ISO-639-1 code) against the artifact
  in the local Gradle cache before writing the exclude list.
- **Fallback:** any build-configure-only trim that reproducibly removes unused
  lingua resources from the base APK (document the mechanism + verify the APK
  diff). Do NOT switch language detection to a downloadable plugin in this
  phase (leaner follow-up may come later; trimming is the in-scope fix) and do
  NOT add new dependencies.

Definition of done for Part A:
- `gradle assembleDebug` green; `gradle assembleRelease` green (R8 minify ON).
- The release APK's `language-models/` payload shrinks from ~80 MB packed to
  effectively the 24 used languages only. Verify with `unzip -l`/`zipinfo` on
  the built APK and record before/after byte counts in the REPORT.
- `LanguageDetectionCore` still detects the same 24 `SUPPORTED` languages —
  `LanguageDetectionEngineTest`/language-detection unit tests stay green (add
  a test that pins the 24-language subset if none exists).
- If an exclude list is added, add a unit test (pure-JVM, no APK needed) that
  pins the `SUPPORTED` key set so the exclude list and the code cannot drift.
